01 / ОСНОВЫ

Имя для человека.
Адрес для подключения.

DNS (Domain Name System) - распределённая система, которая помогает получать информацию по доменным именам, в том числе IP-адреса.

ЗНАКОМАЯ АНАЛОГИЯ
А
Аня+373 00 000 000

Ты выбираешь имя контакта, а телефон использует номер. Для сайта похожую задачу помогает решить DNS.

Доменное имя Имя, которое удобно запомнить человеку.example.com Подробнее +

В имени example.com часть com - домен верхнего уровня, example - имя внутри него. В www.example.com появляется ещё один уровень. Доменное имя и полный URL отличаются: в https://example.com/lesson имя - только example.com. Имя не обязано соответствовать одному IP-адресу.

IP-адрес Адрес, который используется для сетевого взаимодействия.192.0.2.80 Подробнее +

IPv4 - 32-битный адрес, обычно записанный четырьмя числами от 0 до 255. IPv6 - 128-битный адрес, например 2001:db8::80. Это две версии IP. У одного имени может быть несколько адресов, а один адрес может обслуживать несколько сайтов. Здесь 192.0.2.80 и 2001:db8::80 - адреса для документации, а не реальный сервер example.com.

DNS-сервер Помогает получить DNS-ответ на запрос о доменном имени.запрос → ответ Подробнее +

Настроенный DNS-резолвер принимает запрос клиента. Он может ответить из кеша, передать запрос другому резолверу или найти данные через систему DNS. Авторитетный сервер хранит данные своей зоны. Резолвер и авторитетный сервер - разные роли; это не обязательно разные физические компьютеры.

DNS-кеш Временно сохраняет результат, чтобы не искать его каждый раз.TTL = 300 секунд Подробнее +

Кеш может быть у браузера, операционной системы и резолвера. TTL задаёт срок, в течение которого запись обычно можно использовать из кеша без нового получения. TTL 300 означает 5 минут. Это не срок жизни сайта. После истечения TTL запись обычно нужно обновить; время хранения также зависит от реализации и политики кеша.

Имя в браузере

Ты вводишь example.com. Браузеру нужна информация об адресе, чтобы начать подключение.

DNS разрешает имя, а не весь URL. Если соединение уже открыто или подходящий ответ сохранён, новый DNS-запрос может не понадобиться.

DNS помогает найти адрес. Содержимое веб-страницы передают HTTP или HTTPS. В схеме используется адрес для документации.

Что делает резолвер, если ответа нет в кеше?+

Резолвер может передать запрос другому резолверу или выполнять поиск сам.

  1. Корневой серверПодсказывает серверы домена верхнего уровня, например .com.
  2. Серверы .comПодсказывают авторитетные серверы зоны example.com.
  3. Авторитетный серверВозвращает запись из данных своей зоны.

Подсказки и ответы кешируются. Поэтому повторный поиск обычно не проходит всю цепочку заново. Возможны псевдонимы CNAME и другие особенности, которые здесь опущены.

Как отличить обычный ответ, NXDOMAIN и тайм-аут?+
Non-authoritative answer

Сервер ответил, но не является авторитетным для этой зоны. Это обычная ситуация, а не предупреждение о небезопасном ответе.

NXDOMAIN

DNS-ответ сообщает, что запрошенное имя не существует в данном DNS-контексте. Начни с проверки написания имени.

Timed out

Ответ не пришёл вовремя. Возможны проблемы с настройками, сервером или путём до него. Это не то же самое, что NXDOMAIN.

Записи A и AAAA+

DNS хранит записи разных типов. A связывает имя с IPv4-адресом, AAAA - с IPv6-адресом. Для одного имени возможно несколько записей.

Aexample.com → 192.0.2.80AAAAexample.com → 2001:db8::80

Это иллюстративные адреса для документации. DNS также хранит MX для почты, CNAME для псевдонимов и другие типы записей.

Почему помогает кеш и что такое TTL?+

Кеш временно сохраняет ответы. TTL (Time To Live) задаёт срок использования записи из кеша без нового получения. TTL 300 секунд - это 5 минут, а не время работы сайта.

Когда владелец меняет DNS-запись, старые ответы могут оставаться в разных кешах до окончания их срока хранения. Очистка кеша на одном компьютере не очищает все кеши в интернете.

DNS и HTTPS: разные задачи+

DNS отвечает за сведения, связанные с именами. HTTP передаёт запросы и ответы веб-приложения. HTTPS защищает этот обмен с помощью TLS.

Обычный DNS-ответ не доказывает безопасность сайта. DNSSEC проверяет подлинность DNS-данных при корректной цепочке доверия, а DoH и DoT защищают канал DNS-запросов. Это не заменяет проверку HTTPS.

nslookup работает, а сайт не открывается?+

Проверяй следующий этап: доступность сервера и порта, прокси или firewall, TLS и ошибку самого сайта. Посмотри точный текст ошибки браузера.

У браузера может быть собственный DNS-кеш или защищённый DNS. Поэтому nslookup и браузер иногда используют разные пути разрешения. Ввод IP вместо имени не всегда подходит для проверки HTTPS: серверу нужны правильное имя и сертификат.
